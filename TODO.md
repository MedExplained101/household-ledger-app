- [x] Price Refresh Agent — scheduled, detects stale `Catalog` prices, re-scrapes, updates the sheet. Per `household-ledger-architecture.md` Section 5, these reliability constraints are built in from day one rather than retrofitted:
  - 24–48h freshness gate before trusting a newly scraped price
  - Structured JSON schema for every price extraction — never free text
  - Budget for extraction failures — ME101's equivalent agent saw ~38.5% early on; this one has retry/validation logic, not a bare scrape-and-trust path
  - Watch the n8n plan's monthly execution cap — refreshing ~55 catalog items × 2 stores adds up fast if scheduled too often
  - **Live-tested successfully 2026-07-31.** Open Decision #1 resolved as a hybrid design (see below): a "Has Product URL?" branch fetches `Catalog.product_url` directly when set, falls back to a Brave Search API query otherwise, both feeding the same LLM extraction step. Two real fixes made live in n8n during setup and worth remembering for future HTTP Request nodes hitting external APIs: Brave Search rejects n8n's default multi-type `Accept` header (422) — needs an explicit `Accept: application/json` header; Anthropic's Messages API requires an `anthropic-version` header (`2023-06-01`) that isn't part of the API-key credential itself, or it 400s. With both fixed, a real run against 20 stale items produced 12 successful extractions staged in `PriceLog` as `pending` and 8 graceful failures (logged, not crashed) — a 60% first-pass success rate, better than ME101's ~38.5% benchmark. Those 12 pending rows won't promote into `Catalog` until the 24–48h freshness gate passes on a future run — expected, not stuck. `product_url` is still empty for every Catalog row (optional backfill, not required).
